# Pipeline runner

An **external driver** that sequences the build phases — the safe alternative to a single master `/goal`
looping in one session. Generated by the `plan-to-pipeline` skill.

**What it does:** runs **one phase per fresh agent session**, then verifies that phase's `exit_criteria`
**outside the model**. `gate:auto` advances on GREEN; `gate:human` **parks** for an approval token. Resumable
(done phases skipped), **hard-stops on RED** (no retry-loop → no runaway).

## Files
- `phases.yaml` — manifest `{id, name, prompt, exit_criteria(shell→0/1), gate: auto|human, depends_on}`.
- `run.sh` — the driver (generic; do not edit).
- `prompts/<PHASE>.md` — the `/goal` prompt fed to each phase's session.
- `checks/<phase>.sh` — the independent oracle per phase.
- `.state/ approvals/ logs/` — runtime (gitignore these).

## Usage
```bash
cd <this dir>
./run.sh                 # DRY-RUN: state + preview the next phase's check (does nothing)
./run.sh --status        # every phase's state
git checkout -b pipeline-run     # sandbox (driver refuses --execute on main/master)
./run.sh --execute       # run for real, one phase at a time
touch approvals/<ID>.approved && ./run.sh --execute   # clear a human gate, then resume
./run.sh --from <ID>     # resume/force-start at a phase
./run.sh --reset <ID>    # clear a state marker (files untouched)
```

## The hard rule
**Automate sequencing, never judgment.** Each `exit_criteria` is a real command (independent oracle) for
`gate:auto`, or `"true"` + `gate:human` (parks for review). Never let the agent grade its own "done".

## Safety
- Run on a **sandbox branch**; each phase logs a `git reset --hard <rev>` rollback line.
- Keep **DB changes / destructive ops** as `gate: human`.
- `CLAUDE_FLAGS` controls agent permissions — fully-unattended tool use needs a conscious, least-privilege,
  spend-capped choice on a throwaway branch. Never point at production credentials.
- **Read the prompts + checks before `--execute`** — a wrong prompt executes faithfully to a wrong result.

## Env
`CLAUDE_CMD` (default `claude`) · `CLAUDE_FLAGS` (default `--permission-mode acceptEdits`) · `CLAUDE_MODEL` ·
`NOTIFY_CMD` (called with a message on park/red — wire to Slack/email for pings).
