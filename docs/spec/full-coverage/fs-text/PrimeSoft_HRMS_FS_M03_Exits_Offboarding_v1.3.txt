4. API Contracts (complete)
References: §6.4 inventory (endpoint existence, purpose, auth — not restated); §6.2 response envelope; §6.3 rate limiting; §3.7 for 403. Conventions (envelope, pagination, idempotency-key header, error model) are §6.2–6.3 / Foundation FS — referenced, not restated.
4.1 POST /api/v1/separations — Initiate separation
Inventory: §6.4 (Employee self-service · HR Admin · Admin force-initiate). Example payload: §7.5.3.
Request:
{ separation_policy_code, date_of_resignation (date),
target_last_working_day (date), reason_code,
reason_narrative? , recovery_days? (int>=0),
on_behalf_of_employee_id? (HR/Admin force only) }
Response 2xx:
201 { id, employee_id, state:“SUBMITTED”,
proposed_last_working_day (computed VAL-SEP-LWD),
approval_flow_id, links{ self } }
Errors:
400 — malformed body / VAL-SEP-* failure (§5)
403 — employee back-dating own resignation (VAL-SEP-BACKDATE; §3.7 Employee E*)
409 — active separation_records already exists for employee
422 — policy not applicable / category invalid
Idempotency: idempotency-key header (Foundation conv.); duplicate returns original 201. proposed_last_working_day is computed server-side (VAL-SEP-LWD) — client value is not trusted.
4.2 GET /api/v1/separations/{id} — View case
Inventory: §6.4 (Requestor · approver chain · HR Admin · HRBP).
Request:
(none)
Response 2xx:
200 { id, employee, category, state, date_of_resignation,
proposed_last_working_day, final_last_working_day,
reason_code, reason_narrative (masked unless confidential §4.8.1),
approvals[], fnf_summary{cleared,total}, read_only_until }
Errors:
403 — caller outside requestor/approver/HR/HRBP scope (§3.7)
404 — id not found in caller entity scope
reason_narrative masked per §4.8.1 confidential_field_roles + §3.9 projection (§6).
4.3 POST /api/v1/separations/{id}/approve — Approve / object (stage)
Inventory: §6.4 (L1 Mgr · HR Admin). Stage drives §8.4 transition.
Request:
{ stage: 1|2, disposition: “APPROVE”|“OBJECT”|“REJECT”,
comments?, rejection_reason? (required when REJECT/OBJECT),
confirm_one_way_door? (Stage-2 past-dated FLWD) }
Response 2xx:
200 { id, state, approval_stage_1_at|approval_stage_2_at, next_state }
Errors:
400 — REJECT/OBJECT without rejection_reason (§9.4)
403 — caller not the stage approver (§3.7 Manager A* / HR Adm)
409 — stage already actioned / not in approvable state (§8.4)
422 — Stage-2 past-dated FLWD without confirm_one_way_door (MSG-ERR-ONEWAY)
Stage-2 APPROVE with past-dated final_last_working_day requires confirm_one_way_door=true (FR-M03-002).
4.4 POST /api/v1/separations/{id}/revoke — Revoke before LWD
Inventory: §6.4 (Employee own · HR Admin · HRBP · Admin).
Request:
{ reason }
Response 2xx:
200 { id, state:“REVOKED”|“ON_NOTICE”, revoke_requested_at,
revoke_approval_required: bool }
Errors:
403 — caller lacks revoke right (§3.7; SeparationRequests custom permission)
409 — LWD already reached / already separated
If policy block_until_revoke_approval_complete = true, state stays ON_NOTICE and a revoke approval flow starts (default_approval_flow_on_revoke_id §4.8.1); else REVOKED immediately. System-deducted-leave revoke routes to original approval flow per M04 (reference).

The following clarifications reflect the clickable prototype (v2, M11-synced) and the synced BRD v2. They complement — and do not replace — the body of this specification.
Timesheet clearance gate
A Timesheet clearance stage (timesheet / attendance reconciliation) is part of the FnF clearance set. It appears on the FnF clearance board with a clear/pending status and gates Full-and-Final settlement alongside the manager, asset/IT, finance, facilities, attendance/LOP, leave-encashment, compliance/NDA and exit-interview gates. (Ref: BRD §4.8.3 fnf_clearances, §8.4 Separation Workflow.)
Facilities clearance — configurable per-item checklist
Facilities exit clearance (owner role: Office Admin) is a configurable per-item checklist — e.g., ID/access card, parking sticker, locker key, corporate card, library card — with each item independently markable clear/pending. Item lists, clearance stages and separation workflow stages are configured and editable in the separation clearance checklist / workflow screens (HR Admin: cfg-separation-checklist, cfg-separation-workflow), each providing a stage/item edit screen.
Absconding — editable notice dialog
The absconding ‘Send notice’ action opens an editable notice dialog (notice text plus send-via channel: email / registered post) for review before dispatch, rather than sending a fixed notice silently.
Terminology note
The role this FS calls “Separation Admin” is the same role RBAC v1.3 and the prototype label “Offboarding Admin”; “Facilities” clearance is owned by the “Office Admin” role. Align on a single label at reconciliation. # Prototype Sync Addendum — Batch 6: Employee-role Separation review (June 2026)
Reflects the Batch-6 Employee self-service separation review against the clickable prototype (v2). Complements — does not replace — the body of this FS.
Resignation submission
The employee resignation reason is drawn from the Deactivation Reasons master (Voluntary type), not a hardcoded list. The notice period is shown from the employee’s assigned Notice policy (not a fixed value), and the last working day is auto-suggested as the resignation date plus the notice period. The employee acknowledges the notice period and FnF clearance requirements before submitting.
Recovery days — not employee-entered
The employee resignation form does not capture recovery days (notice shortfall). Recovery days are set by the manager, exit admin or HR Admin and approved by HR Admin — they are surfaced to the employee read-only on the separation status, never entered by the resigning employee.
Resignation withdrawal
The employee can request to withdraw a submitted resignation before the last working day, with a reason; the request routes to approval. Withdrawal is an employee self-service action.
Post-submission visibility
After submitting, the employee sees a separation status view: stage, submission date, notice, suggested last working day, a read-only clearance progress list (manager handover, IT assets, finance, HR) with owners, and full-and-final status (which begins after the last working day). Clearance and FnF are actioned by HR and the clearance owners — the employee view is read-only.
Exit interview — not employee self-service
The employee does not complete an exit interview in-system (out of scope for employee self-service); the exit-interview surface remains with HR / exit administration.
Manager-role review (Round 3)
Manager-editable notice period (Stage 1): on manager-initiated separation, when enabled in Notice configuration the manager/reviewer can edit the notice period inline; the Last Working Day recalculates live, a reason is mandatory and the change is audit-logged. Gated by a config flag distinct from the existing edit Recovery Days switch (a corresponding RBAC permission is added). Default off.
