2. Screen Specifications
One subsection per prototype screen (or tight cluster of near-identical screens). Each opens with its references. Field tables carry only build-layer columns; data type/format and rules live in the BRD by reference. Unless a screen overrides them, all screens use the global state standard: empty (zero-data illustration + primary CTA), loading (skeleton rows), error (inline banner referencing a Message Catalogue id in §7), no-permission (section hidden per §6 projection), and partial-data (render available, flag missing).

PrimeSoft HRMS · complements BRD v6.3 · page # Prototype Sync Addendum — Batch 8: Employee-role Performance review (June 2026)
Reflects the Batch-8 review of the employee performance surface (goals, self-review, acknowledgement) against the clickable prototype (v2). Complements — does not replace — the body of this FS.
Review acknowledgement and disagreement
Employee performance acknowledgement is a recorded confirmation (“I acknowledge that I have read and understood my performance review”), consistent with the review configuration where Employee Acknowledgement is enabled in all review templates and mandatory in nearly all. In addition to acknowledging, the employee can add context (a comment on the review) and send the review back / disagree, which routes the review back to the manager for discussion (per the “Allow send back to Employee” review setting).
Goals and self-review
Employees may add and edit their own goals (enabled across all goal plans) and complete a self-review (self-rating and comments), which they submit to their manager. The self-review form and goal add/edit are present and config-aligned.
Manager goal-plan approval — approver capabilities
The Goal Plan Approver is the Manager (config: Goal Plan Approver = Manager, all 40 plans). During plan review/approval the approver can add, edit and delete goals (config: Allow approver to add and edit goals = Yes; Allow employee and approver to delete goals = Yes, all 40), in addition to Approve and Return for redraft (send-back). Goal-plan send-back captures mandatory comments; it depends on the GoalPlan “Enable Sendback” flag, which must be turned on (currently No for all plans — see configuration actions). Manager-created reportee goals are auto-approved because the approver is the manager.
Probation — manager confirms, HR Admin approves
Probation is confirmed by the Manager and approved by HR Admin. The manager workspace exposes the manager’s probation steps (decision queue and the probation-confirmation assessment); the HR-Admin approval stage is exposed under HR Admin only and is not part of the manager navigation. The manager’s probation outcomes are Confirm / Extend / Separate, aligned to the Confirmation Workflow (all three outcomes enabled across stages).
Review submission — mandatory ratings (build note)
On review submission the evaluator’s mandatory ratings and comments must be captured where ReviewKra marks them mandatory (e.g. Evaluator-1 goal rating is mandatory on 26 of 28 reviews) before the review advances to calibration. Send-back to employee is available where Allow send back to Employee is enabled (24 of 28 reviews). These are per-review, configuration-driven validations.
Configuration actions (tenant)
Turn on GoalPlan “Enable Sendback” (currently No, all 40 plans) to allow the approving manager to return a goal plan for redraft.
Manager-role review (Round 3)
Terminology: the Manager appraisal task surface is renamed Team appraisals across menu and screen headings (route id unchanged).
Goal-pending tasks: goal-plan submission, quarterly check-in and review-stage actions are surfaced as task types in the unified Tasks list (Employee and Manager), in addition to the in-module Goals & reviews screens.
