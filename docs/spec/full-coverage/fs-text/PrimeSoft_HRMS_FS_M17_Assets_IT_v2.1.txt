References — BRD FR-M17-002, 006; §4.13 entities; §3.7.2 RBAC; prototype page “my-assets”.

Employee view of assets currently assigned to them, with acknowledgement of receipt/return.
Key fields &** controls. **Asset list (asset_tag, category, make/model, assigned_at, condition); acknowledgement status; Asset Acknowledgement Form viewer.

Service Catalog (prototype: service-catalog)
References — BRD FR-M17-010; §4.13 entities; §3.7.2 RBAC; prototype now surfaced within prototype page “raise-ticket” (no standalone main-menu screen).
Purpose.
Catalog items (hardware, software, access) are requested within Raise Ticket — the service catalogue is no longer a standalone main-menu screen. The request type is chosen from a dropdown sourced from the Service-Catalogue master (owned and configured by the Service Desk Admin).

3. Interaction & Navigation Flows
References — BRD FR-M17-002/003/004/007/008; cross-module M02 §8.5 (onboarding) and M03 §8.4 (separation); M17 state machines now in BRD §8.9 (asset) and §8.10 (ticket).
These map screen-to-screen transitions; the underlying state changes are governed by the FRs. Job-driven transitions reference §8.1 (scheduled jobs).
3.1 Provisioning → assignment (new joiner)
M02 emits m02.it_provisioning_task_assigned (≈5 working days before start) → it-asset-requests.
IT Asset Manager confirms/substitutes the role-family bundle; stock check; Reserved.
it-asset-assignment assigns asset(s); acknowledgement form issued → employee acknowledges on my-assets → asset In Use.
On completion M17 emits m17.it_provisioning_complete → M02 marks onboarding task done (FR-M17-007).
3.2 Separation → IT clearance → recovery
M03 reaches LWD-7 → fnf_clearances row (dept = IT) → clearance-it-assets (resolved: M03 FS owns the screen shell + FnF orchestration; M17 owns the asset-return + recovery panel and the clearance event contract).
IT Admin records each return (returned_at, return_condition). All returned → IT clearance CLEARED.
Damaged-beyond-repair / missing → recovery exception (assets.clearance_exception) to M03 with recommended value; HR Admin decides waive/partial/full (FR-M17-004).
3.3 Ticket lifecycle
raise-ticket / service-catalog → service_tickets → sd-queue (routed by category) → sd-ticket-work.
In Progress → Resolved is blocked until Resolution Notes populated (FR-M17-008). Resolved auto-closes after the 3-business-day reopen window (job §8.1).
Pending pauses SLA timers; breach fires the configured escalation action (D4; job §8.1).
Any ticket that held P1 → on Closed, post-mortem auto-opens on it-postmortems (FR-M17-013).

Validation id
	Applies to
	Rule

VAL-AST-TAG
	asset_tag
	Unique per tenant; physical tag format ORG-{CAT}-{5d}; internal AST-{entity}-{6d} immutable, 1:1 with physical tag.

VAL-AST-SERIAL
	serial_number
	Unique within asset_category (per FR-M17-001).

VAL-AST-STATE
	asset state change
	Only transitions in the allowed-transitions table accepted; Disposed / Written Off locked read-only; soft-delete only.

VAL-AST-CAP
	purchase_value
	≥ capitalisation threshold (₹15,000 default) → capitalised; ≥ tagging threshold ($100/₹8,500 default) → must be tagged.

VAL-TKT-ASSET
	ticket.asset_id
	Mandatory for Hardware/Software/Network categories; optional for Account/Access and Service Request — Account.

VAL-TKT-RESNOTE
	resolution_notes
	Non-empty (root cause + steps) required before In Progress → Resolved; no override.

VAL-TKT-DUP
	ticket creation
	Flag potential duplicate on creator + category + asset + 30-minute window.

VAL-CAT-JUST
	catalog request
	Business justification mandatory; if required_by < fulfilment SLA → set ‘Expedite required’.

VAL-CSAT
	csat_score
	Integer 1–5; submission window 72 h after Closed; score < 3 sets low-score flag.

Page # Prototype Sync Addendum — Batch 9: Employee-role Assets & Tickets review (June 2026)
Reflects the Batch-9 review of the employee assets and IT-ticket surface against the clickable prototype (v2). Complements — does not replace — the body of this FS.
Asset self-service actions
The employee’s “My assets” list now supports self-service actions on each assigned asset: acknowledge assignment, report issue / lost, and request return (captured with notes and routed to IT). The list is no longer view-only.
Ticket subcategory
On the raise-ticket form, sub-category is a dependent dropdown populated from the selected category (e.g., Hardware Fault → Laptop / Desktop / Monitor / Peripheral / Printer). Priority P1 remains capped (requires Service Desk Admin).
Knowledge base
Knowledge-base category browse opens the articles for the chosen category rather than a placeholder. The service-catalog items and knowledge-base categories should be driven from the catalog-items and KB configuration so the employee surface stays in sync with what Service Desk Admin configures.
